# ComfyUI-to-App / Consumer-Studio Frontends for Self-Hosted Deployment

## Which candidates exist, and are they actually self-hostable open source (not SaaS-only)?

### Takeaway
Most named candidates ARE genuinely open-source and self-hostable, but with important caveats: ViewComfy is AGPL-3.0 (copyleft — flag for commercial hosting review), Comfy Deploy is more of a developer/API deployment platform than a consumer-facing studio UI, and several "Higgsfield/Krea/Freepik open-source alternative" hits are either (a) not backed by ComfyUI at all (e.g. Open-Higgsfield-AI uses Muapi.ai, not ComfyUI) or (b) thin marketing/directory pages rather than real projects. Comfy Org's own "App Mode / App Builder / ComfyHub" (shipped ~2026) is the most credible first-party option, built directly into the official ComfyUI frontend, but ComfyHub itself (the publishing/sharing layer) appears to be a hosted service in preview rather than something you self-host end-to-end.

### Cited Findings
- **ViewComfy** (github.com/ViewComfy/ViewComfy) — 668 stars, 608+ commits, **license AGPL-3.0**, Next.js/TypeScript/React stack with Clerk (auth) and Sentry, connects to ComfyUI via a `workflow_api.json` drop-in / API endpoints, explicitly supports image, video, and text outputs. Free self-hosting via Docker is supported; "ViewComfy Cloud" is a paid hosted tier adding user management, billing, and shareable links — but the core app-builder is self-hostable. — [GitHub](https://github.com/ViewComfy/ViewComfy)
- AGPL-3.0 is a strong copyleft license: modifying and running ViewComfy as a network service (SaaS) can trigger source-disclosure obligations under AGPL §13 — this needs legal review before using it as the core of a commercial hosted product. — [GitHub license file](https://github.com/ViewComfy/ViewComfy)
- **Comfy Deploy / ComfyDeploy** (github.com/comfy-deploy/comfydeploy) — 455 stars, **license GPL-3.0**, described as "ComfyUI for teams" / a "Vercel-like deployment platform" for ComfyUI workflows. Stack: Next.js frontend, Node.js/Bun backend, Neon (Postgres), Clerk auth, AWS S3, Modal for compute, Docker/OrbStack for local dev. The team states they are "open-sourcing the ENTIRE CLOUD PLATFORM" and it can be self-hosted, but it's positioned as developer/API infrastructure (workflow deployment, versioning, team collaboration) rather than a polished end-consumer creative studio UI. — [GitHub](https://github.com/comfy-deploy/comfydeploy), [comfydeploy.com](https://www.comfydeploy.com/), [Y Combinator listing](https://www.ycombinator.com/companies/comfy-deploy)
- Comfy Deploy is a Y Combinator-backed startup (accepted "after just a few weeks of meeting" following its 2023 start), which is relevant maintainer-risk context — it's a funded startup's OSS component, not a hobby project, but roadmap priorities may skew toward their own paid cloud product. — [YC company page](https://www.ycombinator.com/companies/comfy-deploy)
- A separate, older repo **BennyKok/comfyui-deploy** ("An open source `vercel` like deployment platform for Comfy UI") appears to be the origin/predecessor of the comfy-deploy org's product; its README references the newer `comfy-deploy/comfydeploy` org repos as the actively maintained implementation. Exact fork/rename relationship between the two repos was not fully confirmed from available pages. — [GitHub](https://github.com/BennyKok/comfyui-deploy) (Gap: precise history unconfirmed)
- **Comfy Org's own "App Mode / App Builder / ComfyHub"** shipped in 2026 as a first-party feature of the official ComfyUI frontend (supported from front-end version 1.41.13+). App Mode lets a workflow author expose a simplified input/output interface (image upload, text prompt, model picker, output preview) without touching the node graph, so it can be "handed to clients or teammates." Every App Builder app can be shared via a single URL encoding the workflow configuration. — [Comfy Org blog](https://blog.comfy.org/p/from-workflow-to-app-introducing), [docs.comfy.org App Mode guide](https://docs.comfy.org/interface/app-mode)
- **ComfyHub**, the marketplace/publishing layer announced alongside App Mode, "launches today in preview with a curated selection of workflows," and creators must apply via an interest form for publishing access — this reads as a Comfy Org-hosted discovery/sharing service, not something you self-host as your own branded product; it complements (does not replace) self-hosting App Mode itself, which lives inside the open-source ComfyUI frontend you already run. — [Comfy Org blog](https://blog.comfy.org/p/from-workflow-to-app-introducing), [Yahoo Finance coverage](https://finance.yahoo.com/news/comfyui-launches-app-mode-app-160000673.html)
- Since App Mode is built into `Comfy-Org/ComfyUI_frontend` / `Comfy-Org/ComfyUI` itself, it inherits **ComfyUI core's license (GPL-3.0)**, per multiple secondary sources describing ComfyUI as "GPL-3.0 licensed." — [opensourcealternatives.to](https://www.opensourcealternatives.to/item/comfyui) (Gap: not independently verified against the primary LICENSE file in this pass)

### Inferences
- If low legal risk is a priority, Comfy Org's own App Mode/App Builder is the safest license-wise (it's the same license as ComfyUI core, which the team is presumably already comfortable running) and has zero integration risk since it's literally the official frontend — but it is more limited/less "studio-polished" than a dedicated consumer product and its marketplace half (ComfyHub) is not self-hostable.
- ViewComfy looks the most feature-complete as a dedicated "wrap a ComfyUI workflow in a nice web app" tool, but AGPL-3.0 requires a compliance decision (e.g., open-sourcing modifications, or a commercial license from ViewComfy if one exists — not confirmed) before using it as the base of a paid product.
- Comfy Deploy is best understood as ops/deployment tooling (CI/CD-style workflow versioning and API hosting) for teams running many ComfyUI workflows, not as the polished front-of-house UI end users would see — it would need a separate consumer UI layered on top, or used purely as backend infrastructure.

### Gaps
- Exact last-commit dates (freshness) for ViewComfy and Comfy Deploy were not retrievable from the fetched pages (only commit counts, not timestamps).
- No direct confirmation of a commercial/dual license offered by ViewComfy to escape AGPL obligations.
- The precise repo lineage (fork vs. rewrite) between `BennyKok/comfyui-deploy` and `comfy-deploy/comfydeploy` was not fully confirmed.

## What is "Open Higgsfield AI" / OpenCanvas, and do they actually run on ComfyUI?

### Takeaway
Neither of the two "Higgsfield-branded open source alternative" projects found actually runs on a self-hosted ComfyUI backend — both are thin frontends over third-party paid model APIs, which disqualifies them as candidates for "glue an open frontend onto our own headless ComfyUI backend" unless significantly modified.

### Cited Findings
- **Autom8AI/Open-Higgsfield-AI** — 600 stars, 144 forks, 66 commits, **MIT licensed**. Stack: Next.js 14 (App Router), React 18, Tailwind CSS v3, npm workspaces monorepo. **It does not use ComfyUI as a backend** — it calls Muapi.ai, a third-party unified API gateway, via `POST /api/v1/{model-endpoint}` then polling `GET /api/v1/predictions/{request_id}/result`; users must supply their own Muapi.ai API key (i.e., you still pay a hosted inference provider per generation, you don't get free/local GPU inference). — [GitHub](https://github.com/Autom8AI/Open-Higgsfield-AI)
- Open-Higgsfield-AI is self-hostable (one-click desktop installers for macOS/Windows, browser setup) and the UI is described as highly polished — dual-mode studios, multi-image reference picker (up to 14 images), generation history, cinema camera controls, glassmorphic styling — and claims support for 40+ text-to-video and 60+ image-to-video models including "Wan 2.2 Speech to Video," Kling, Sora, Veo, Seedance 2.0 (all via the Muapi.ai gateway, not local inference). — [GitHub](https://github.com/Autom8AI/Open-Higgsfield-AI)
- The repo is under the Autom8AI org and was forked from `Anil-matcha/Open-Generative-AI`; bylines point to "@anilmatcha," suggesting a single developer or small team rather than a funded org — moderate maintainer risk (no evidence of institutional backing). — [GitHub](https://github.com/Autom8AI/Open-Higgsfield-AI)
- **opencanvasai/OpenCanvas** — only 40 stars, 66 commits, **MIT licensed**, described as "Open-source alternative to Higgsfield, weavy & Comfy UI." Stack: Electron + Vite, React-style components, Playwright tests — i.e., it's positioned as a desktop node-based AI editor, not confirmed to integrate with a self-hosted ComfyUI backend from the fetched content. — [GitHub](https://github.com/opencanvasai/OpenCanvas)
- Star count (40) and lack of detailed backend documentation suggest OpenCanvas is early-stage / low-traction relative to other candidates. — [GitHub](https://github.com/opencanvasai/OpenCanvas)

### Inferences
- Neither "Higgsfield-named" project is a good fit for the stated goal (headless ComfyUI backend + polished frontend) as-is — Open-Higgsfield-AI's architecture (call out to Muapi.ai) would need to be re-plumbed to hit a self-hosted ComfyUI API instead, which is a non-trivial rewrite of its generation/polling layer, though its UI/UX layer could plausibly be reused if abstracted from the backend calls.
- The UI quality of Open-Higgsfield-AI (per its own README/screenshots) looks closer to the Higgsfield/Krea aesthetic than most ComfyUI-native frontends, making it a candidate worth a deeper UI-only evaluation even if the backend integration must be replaced.

### Gaps
- No independent (non-repo-README) review, screenshot, or user testimonial was retrieved to verify Open-Higgsfield-AI's UI quality claims — this came from the project's own marketing copy in the README, so it should be treated as self-reported, not independently confirmed.
- Whether Open-Higgsfield-AI's codebase could be feasibly retargeted to a ComfyUI backend (vs. requiring a full rewrite) was not assessed — would need a code-level review, not just a README fetch.

## What other consumer-style / non-developer ComfyUI frontends exist, and how do older projects like ComfyBox and StableSwarmUI fit in?

### Takeaway
A large "awesome list" (light-and-ray/awesome-alternative-uis-for-comfyui) catalogs many alternative UIs; of these, SwarmUI (successor to Stability AI's StableSwarmUI) is by far the most established and actively maintained "hybrid" option (simple tab for casual users, full node graph for power users), while ComfyBox — an early, well-known alternative frontend — is effectively abandoned, with only unofficial community forks keeping it alive.

### Cited Findings
- **SwarmUI** (github.com/mcmonkeyprojects/SwarmUI) — 4.6k stars, 5,013+ commits, **MIT License**. Backend: C# (.NET 8, moving to .NET 10), with Python integration; frontend uses Bootstrap/jQuery/Select2 (not a modern React/Next.js SPA). It **auto-installs and drives ComfyUI as a backend** (also supports AUTOMATIC1111/stable-diffusion-webui as an alternate backend). Positioned as a hybrid: a simplified "Generate" tab for casual/beginner use plus a "Comfy Workflow" tab exposing the raw ComfyUI node graph for power users. Confirmed video model support includes "MiniMax H3, Wan, LTX-2, etc." (exact Wan version, e.g. 2.2, not confirmed in the fetched excerpt). — [GitHub](https://github.com/mcmonkeyprojects/SwarmUI)
- **StableSwarmUI → SwarmUI history**: Stability AI announced on June 21, 2024 it would stop maintaining StableSwarmUI due to financial/organizational restructuring; lead developer Alex "mcmonkey" Goodwin migrated the project to the independent `mcmonkeyprojects` GitHub org and renamed it SwarmUI, continuing it as a community-driven project outside corporate control. A migration script (`migrate-windows.bat` on Windows, manual git remote repoint on Linux/Mac) was provided for existing users. The original `Stability-AI/StableSwarmUI` repo still exists but is no longer the active project. — [Migration Guide discussion](https://github.com/mcmonkeyprojects/SwarmUI/discussions/2), [SwarmUI GitHub](https://github.com/mcmonkeyprojects/SwarmUI)
- **ComfyBox** (github.com/space-nuko/ComfyBox) — an early, well-known "customizable Stable Diffusion frontend for ComfyUI," originally posted as a "proof of concept for an alternative frontend to ComfyUI" in a Comfy-Org/ComfyUI GitHub discussion. The original author appears to have moved on; the main visible continuation activity is unofficial community forks (e.g., `ChessScholar/ComfyBox_Reopened`, described by its own maintainer as "a very broken down version of spacenuko's original ComfyBox concept"). This strongly suggests ComfyBox proper is **abandoned/unmaintained** as of 2026. — [Original discussion](https://github.com/comfyanonymous/ComfyUI/discussions/440), [space-nuko/ComfyBox](https://github.com/space-nuko/ComfyBox), [ChessScholar fork](https://github.com/ChessScholar/ComfyBox_Reopened)
- The **light-and-ray/awesome-alternative-uis-for-comfyui** GitHub list catalogs many more niche/smaller projects, including: **Promptus/CosyUI** (desktop app, one-click install, 150+ templates, one-time-license/paid model — not fully free/open), **Nexus BTA** (local AI studio embedding a ComfyUI runtime with a simplified UI plus graph access), **ComfyAgent** (desktop studio, 600+ templates, ~10MB pure-Python executable, Chinese-to-English prompt auto-enhancement), **Stability Matrix** (multi-platform package manager/launcher for SD and ComfyUI, active community), **Metastable** (project-based image organizer, explicitly work-in-progress), **somni** (desktop/mobile frontend with a "Gemini-style easy mode," IP-Adapter support, mobile-friendly gallery), and **ImageGen Studio** (minimalist local web UI/CLI, no node graph). — [awesome-alternative-uis-for-comfyui](https://github.com/light-and-ray/awesome-alternative-uis-for-comfyui)
- Separately, **AI Images Studio** (facio-wang/ai-images-studio) is a self-hosted local text-to-image web UI built on ComfyUI + FastAPI + Vue3, with conversational AI painting, smart background removal, a model center, an asset library, GPU monitoring, and a built-in MCP server; ships as a single Docker container (frontend + backend + SQLite) for one-click self-hosting. — [GitHub](https://github.com/facio-wang/ai-images-studio)

### Inferences
- SwarmUI is the strongest "proven, actively maintained, MIT-licensed" candidate by raw popularity and maintenance signals (4.6k stars, thousands of commits, community-driven after surviving a corporate abandonment event), but its frontend stack (server-rendered C#/.NET + Bootstrap/jQuery) is dated relative to a Krea/Higgsfield-style modern SPA, and it visually reads more like a "powerful generation console" than a slick consumer studio product — likely needs a custom skin/theme pass to hit the desired "non-technical, polished" bar.
- ComfyBox should be excluded from serious consideration given the abandonment signal and reliance on unofficial forks — using it would mean effectively adopting and maintaining an orphaned codebase.
- Several of the smaller "awesome list" entries (Promptus/CosyUI, Stability Matrix, ComfyAgent, Nexus BTA) are desktop-app-first products, which conflicts with the "single rented Runpod GPU, web-hosted studio" deployment model implied by the objective — they'd need adaptation or are simply the wrong shape (local installer vs. multi-tenant web app) for this use case.
